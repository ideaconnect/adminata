Tokens are copied verbatim from TailAdmin's style.css into a `@theme static` block (minus the font/breakpoint resets), with the documented `@custom-variant dark (&:where(.dark, .dark *))` and a semantic z-index ladder (overlay 10 … header 50, modal 60, popover 70) that resolves TailAdmin's header/modal z-99999 tie; brand colour is build-time in @theme but runtime-overridable by redefining the same `--color-brand-*` variables, which is exactly how the 12 legacy `skin-*` files are reimplemented. Emission mechanism: every `.adm-*` primitive is an `@utility` (so the compat layer and user CSS can `@apply` it) forced into the prebuilt app.css by a generated `@source inline()` safelist; the Bootstrap-3/AdminLTE compat layer is plain `@layer components` rules namespaced under `.sonata-bc` and built as a separate `compat-bootstrap3.css` via `@reference "./app.css"`; PHP-emitted grid/box strings are kept and translated by `sonata_grid_class`/`sonata_box_class` filters whose outputs are safelisted. The merged inventory covers ~180 Bootstrap/AdminLTE classes (grid, box/panel, small-box/info-box/callout, login-box, user-header, buttons, labels/badges, alerts, forms, tables, navs/tabs/dropdowns, modal, glyphicons) with exact @apply recipes citing TailAdmin partials, and lists the Tailwind collisions (`fixed`, `collapse`, `container`, `table`, `border`) with their resolution in an `@layer sonata-overrides` layer plus `@source not inline("collapse")`. Every rule of Sonata's six SCSS files is mapped to kept/utility/compat/dropped. Third-party CSS (Tom Select theme on the same `.ts-*` selectors the real app skins, flatpickr theme verbatim, SortableJS ghost classes, FA6 woff2-only, Outfit self-hosted), a size budget and a CI contract check (PostCSS-parsed selector assertions plus a dead-class lint of templates) are specified, and a per-app compile recipe for AssetMapper/Encore/Vite with the remove_stylesheets/extra_stylesheets swap closes the report. All Tailwind v4 semantics relied on are enumerated (T1–T12) and flagged for verification because no Tailwind v4 package exists locally.

KEY FINDINGS:
 - Compat layer must be @layer components (always emitted); an @utility-based compat layer would be purged from the prebuilt app.css because user templates are never scanned (Tailwind v4 emits @utility only when seen) — js-assets §7.4 confirmed as the governing constraint.
 - .adm-* primitives must nevertheless be @utility, because Tailwind v4 @apply only accepts utilities, and the compat layer's recipes are written as `@apply adm-*`; emission in the prebuilt file is guaranteed by a generated @source inline() safelist plus a CI selector-contract check.
 - @theme static (not plain @theme) is required so every token variable exists for user stylesheets and the 12 skin files; brand colour stays build-time in @theme and is re-themed at runtime by redefining the same --color-brand-* variables — the --adminata-* indirection proposed by tailadmin-catalog §5.1 is rejected as redundant.
 - TailAdmin's z-index tokens (header and modal both z-99999: header.html:3, profile-info-modal.html:3, Modal index.tsx:57) are replaced by a semantic ladder overlay 10 / sticky 20 / dropdown 30 / sidebar 40 / header 50 / modal 60 / popover 70 / toast 80; Tom Select (default z 10) and flatpickr (default 99999) are pinned to z-popover.
 - Real Tailwind collisions found: body class `fixed` (standard_layout.html.twig:93) must be dropped and neutralised for copied body_attributes; `collapse` (ORM block_audit.html.twig:33, block-bundle) is hidden by Tailwind's visibility:collapse unless excluded via @source not inline("collapse") plus an @layer sonata-overrides rule; Sonata's `div.border` rule (layout.scss:14-19) must be dropped; `.container` must never be defined.
 - The real app adds classes beyond every prior inventory: btn-secondary (BS4 name), user-header bg-light-blue, login-page/login-box/login-box-body/login-box-msg, has-feedback/form-control-feedback, glyphicon glyphicon-user/lock, progress-striped, and an app-defined .mt-10{margin-top:10px} that collides with Tailwind's mt-10.
 - Sonata 4.43 ships Bootstrap 3's glyphicons font (src/Resources/public/fonts/glyphicons-halflings-regular.*) so the documented login recipe works today; adminata should carry the woff2 + class map inside compat-bootstrap3.css (~30 KB) or rewrite the recipe.
 - Grid translation needs a base span: Bootstrap col-md-6 is full-width below md, so sonata_grid_class must emit `col-span-12 md:col-span-6`, and the compat `.row > [class*=col-]` rule must apply col-span-12; `.row > .clearfix` must be hidden because float clearers become grid items (list_outer_rows_mosaic.html.twig:94,97).
 - The sidebar-menu/treeview/treeview-menu/active classes are emitted by adminata's own Menu/sonata_menu.html.twig (MenuTest.php:41 selects .sidebar-menu .dynamic-menu a), so their styling belongs in components.css, not the removable compat file; TailAdmin's menu-item* helpers are kept as @utility with the React currentColor icon variants.
 - Test-pinned class strings that the theme must keep emitting alongside .adm-*: `col-sm-3 control-label required`, `help-block sonata-ba-field-help help-text`, `form-group has-error`, `alert alert-danger` + `list-unstyled` (tests/Form/AdminLayoutTest.php:31,113,163,178), `<div class="checkbox"><label>…<span class="control-label__text">` (FormChoiceWidgetTest.php:47), `.modal-content button[name=btn_create]` (Mongo fork ReferenceMappingTest.php:61).
 - Every rule of styles.scss, layout.scss, tree.scss, flashmessage.scss, readmore.scss and admin-lte-fas.scss is dispositioned; roughly 40% is dropped (Bootstrap-2/AdminLTE-layout leftovers, filter_legend, div.connection), the rest becomes token-based component CSS keeping the sonata-* hook classes (stuck, sonata-ba-list-row-selected, sonata-readmore*, sonata-tree*, required::after, read-more-*, sonata-ba-modal-edit-one-to-one).
 - Tom Select must be themed on the vendor's own selectors (.ts-wrapper/.ts-control/.ts-dropdown/.ts-dropdown-content, tom-select.default.css:15-116) without importing the vendor stylesheet, because the real app already skins those selectors for ux-autocomplete fields (sonata-overrides.scss:66-100).
 - Font Awesome: ship FA6 Free all.css + v4-shims as a separate removable fontawesome.css with four woff2 files only (Sonata today ships FA5 in four formats = 1.1 MB of a 2.1 MB fonts dir); the real app loads FA 6.7.2 from cdnjs and uses FA6-only names plus FA4 names via shims.
 - Size budget: app.css ≤ 140 KB / compat ≤ 60 KB / fontawesome ≤ 130 KB / fonts ≤ 400 KB versus Sonata's 345 KB app.css + 2.1 MB fonts; the 12 AdminLTE skin files (56 KB) become 12 sub-1 KB token files published at the same admin-lte-skins/ path so SonataAdminExtension.php:94-100 and remove_stylesheets keep working.
 - Per-app compilation is supported for AssetMapper+tailwind-bundle, Encore and Vite by making assets/css/adminata.css a plugin-free importable source (another reason to reject @tailwindcss/forms, which the standalone CLI cannot resolve), with @source globs over vendor/idct/adminata/src/Resources/views, the app's templates and src/Admin, and the remove_stylesheets/extra_stylesheets swap.

RISKS:
 - [high] Tailwind v4 semantics T1–T11 are asserted from knowledge without a local package; if @apply cannot consume @utility names across @reference, or @theme static does not exist in the pinned version, the components/compat split must be reworked. || MITIGATION: Fixture test as the first task; fallback design is to duplicate recipes as raw utilities in compat (no @apply adm-*) and to define .adm-* in @layer components (losing variant support).
 - [high] An @utility adm-* omitted from the generated safelist ships nowhere in the prebuilt app.css and silently breaks user templates that use it. || MITIGATION: safelist.css and contract.json are generated, committed and asserted in CI; the dead-class lint catches template usage of unknown classes.
 - [medium] Compat layer namespacing under .sonata-bc does not cover ajax_layout fragments or user pages that load app.css without the body class. || MITIGATION: Wrap ajax_layout output in a div.sonata-bc; document that the compat layer requires a .sonata-bc ancestor.
 - [medium] Runtime brand override relies on utilities compiling to var(--color-*) and color-mix for opacity modifiers; if a future Tailwind minor inlines literal colours, skins stop working. || MITIGATION: Pin the Tailwind version; CI asserts app.css contains var(--color-brand-500) inside a bg-brand-500 rule.
 - [medium] Tailwind's `.collapse` utility hides Bootstrap accordion panes in sibling bundle templates whenever an app build scans vendor/. || MITIGATION: @source not inline("collapse") in both the bundle build and the documented recipe, plus the @layer sonata-overrides rule.
 - [low] Font Awesome 6 renames a few FA5 names used by Sonata docs and user admins; FA6's v4 shims do not cover FA5→FA6 renames. || MITIGATION: Add a small fa5-shims section to fontawesome.css for the ~20 renamed icons found in Sonata sources and docs.
 - [low] Size budget may be exceeded by the FA6 solid font and the glyphicon map, pushing first paint of the admin above Sonata's current payload on slow links. || MITIGATION: fontawesome.css and compat are separate removable files; consider an SVG-sprite icon mode later (php-compat §3 option B).
