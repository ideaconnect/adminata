## 0. Executive summary

1. **TailAdmin free is a page template, not a component library.** It ships ~40 partials and one `style.css` whose only real "components" are 16 `@utility` classes for the sidebar menu and two scrollbar helpers (`TA/src/css/style.css:190-267`). Everything else is *inline class recipes* repeated verbatim across pages (e.g. the 300-character input class string appears 42 times). For adminata this is actually convenient: the recipes can be copied into Twig macros / `@utility` definitions and reused, with no upstream component API to track.
2. **Coverage vs Sonata's needs is roughly 45 %.** Present and directly reusable: page shell (sidebar/header/overlay/preloader), collapsible sidebar with persisted state, dark mode, cards, tables, badges, buttons, alerts, avatars, basic form controls (input/select/textarea/checkbox/radio/switch/file/dropzone/date via flatpickr), a simple modal, a "kebab" dropdown, a segmented tab control, pagination (Next only), breadcrumb, 404 and sign-in/up pages. **Absent** (must be built or sourced): sortable table headers, batch-checkbox column and row selection, per-row action button group, filter panel + filter-list dropdown with counter, per-page select, mosaic grid, tree view, form/show tabs with error badges, collapsible box groups, **stacked/nested large modals loaded via AJAX**, inline edit popover (x-editable), searchable/ajax/tags/sortable select (select2), collection rows (add/delete/sort), date-time *range* pickers, flash-message stack with collapse, breadcrumb dropdowns, multi-column "add" menu, sticky action bar, delete/batch confirmation, ACL matrix, history list + revision compare diff, dashboard block grid, read-more truncation, ajax spinner, toasts, tooltips, keyboard focus management, RTL.
3. **Interaction layer.** TailAdmin uses Alpine.js 3 + `@alpinejs/persist` for *all* UI state (`TA/src/js/index.js:6-20`), with zero `aria-*` attributes, zero `x-transition`, zero focus trapping (`grep` counts: `aria-` 0, `x-trap` 0, `x-transition` 0 across `TA/src`). Sonata's behaviours are jQuery + Bootstrap 3 plugins + 9 Stimulus controllers (`SA/assets/js/app.js:14-48`, `SA/assets/js/controllers/*`). The recommended split for adminata: keep Sonata's Stimulus controllers (they are DOM-agnostic and are part of the public JS surface: `sonata-*` identifiers, `sonata-admin-append-form-element` events), add new Stimulus controllers for what Bootstrap/jQuery used to do (dropdown, modal, tabs, collapse, alert dismiss, tooltip), and use Alpine only for the pure-presentation toggles TailAdmin already encodes (sidebar, dark mode, header menus). Avoid loading both Alpine *and* writing app logic in it: Sonata's public event contract is Stimulus/DOM-event based.
4. **Drop-in risk is concentrated in three places**: (a) class names that user templates, Panther tests and persistence bundles select on (`.sonata-ba-*`, `.btn.btn-*`, `.modal-content`, `.field-container .sonata-ba-action[title="Add new"]` — see `MDB/tests/Functional/ReferenceMappingTest.php:35,61`), (b) the FontAwesome string contract of `parse_icon` (`SA/src/Twig/IconRuntime.php:20-38` throws unless the icon starts with `fa `, `fas `, `far `, `fab `, `fal `, `fad ` or is raw HTML), which is used by every admin group icon and every `list_mode` icon, and (c) global JS objects that third-party bundles call (`window.Admin.shared_setup`, `Admin.setup_select2`, `jQuery`, `$`, `global.stimulus`, `global.sonataApplication` — `SA/assets/js/app.js:51-54`, `SA/assets/js/admin.js:14-25`).
5. **Browser floor moves.** Sonata builds with browserslist `defaults` (`SA/package.json` "browserslist": ["defaults"]) and Bootstrap 3 renders on anything. Tailwind v4 requires Safari 16.4+, Chrome 111+, Firefox 128+ (needs `@property`, `color-mix()`, cascade layers). TailAdmin's `.browserslistrc` (`last 1 version`, `>1%`, `not dead`) is only used by autoprefixer and does not lower that floor. This must be a documented, deliberate break.

## 1. Design tokens and global CSS (`TA/src/css/style.css`)

### 1.1 Imports and dark-mode strategy

| Line | Declaration | Note for adminata |
|---|---|---|
| 1-2 | `@import url("https://fonts.googleapis.com/css2?family=Outfit:wght@100..900&display=swap") layer(base);` | **Network dependency.** An admin bundle must not phone Google on every page: self-host Outfit (SIL OFL 1.1 — compatible with MIT bundle, keep the OFL notice) via `@fontsource/outfit` or ship WOFF2 under `src/Resources/public/fonts/`, exactly as Sonata does for Source Sans Pro (`SA/assets/scss/app.scss:18-26`, `SA/src/Resources/public/fonts/`). Alternatively fall back to `--font-sans` system stack and make the font a theme token (see §6). |
| 4 | `@import "tailwindcss";` | Tailwind v4 CSS-first config; no `tailwind.config.js` anywhere in the three templates. |
| 6 | `@custom-variant dark (&:is(.dark *));` | Class-based dark mode. The `.dark` class is put on `<body>` by Alpine (`TA/src/index.html:19`) in the HTML template, and on `<html>` by React (`TAR/src/context/ThemeContext.tsx:33-37`). Adminata should put it on `<html>` (avoids flash-of-light-mode: can be set by an inline script before first paint, and Sonata's `body_attributes` block remains free for `sonata-bc`/skin classes). |

`@tailwindcss/forms` is a devDependency of the HTML template (`TA/package.json:21`) and a dependency of Next (`TAN/package.json` line "@tailwindcss/forms") but **no** `@plugin "@tailwindcss/forms"` line exists in any of the three stylesheets (grep of `style.css`, `index.css`, `globals.css` returned nothing). All form styling is explicit utility classes. Adminata should decide explicitly; recommendation: do *not* add the forms plugin (it resets `<select>`/`<input>` globally and would fight Symfony form themes users inject), keep explicit recipes.

### 1.2 `@theme` tokens (lines 8-166) — complete list

**Fonts** (9-10): `--font-*: initial` (wipes Tailwind's `font-sans/serif/mono`!), `--font-outfit: Outfit, sans-serif`. Consequence: `font-sans` no longer exists; every text inherits `font-outfit` from the body rule (274-276). Adminata should *not* wipe `--font-*`; define `--font-sans: var(--adminata-font, Outfit), ui-sans-serif, system-ui, sans-serif` instead so `font-mono` etc. still work for users.

**Breakpoints** (12-20): `--breakpoint-*: initial`, then `2xsm 375px`, `xsm 425px`, `sm 640px`, `md 768px`, `lg 1024px`, `xl 1280px`, `2xl 1536px`, `3xl 2000px`. Layout switches happen at `lg` (sidebar becomes static, `TA/src/partials/sidebar.html:3`), `md` (React `SidebarContext` "mobile" is `< 768`, `TAR/src/context/SidebarContext.tsx:38`), `xl` (search input width 430px, dashboard columns).

**Type scale** (22-37): `text-title-2xl` 72/90, `text-title-xl` 60/72, `text-title-lg` 48/60, `text-title-md` 36/44, `text-title-sm` 30/38, `text-theme-xl` 20/30, `text-theme-sm` 14/20, `text-theme-xs` 12/18. Tailwind defaults (`text-xs`…`text-2xl`) are kept and used interchangeably in the markup (e.g. tables use `text-theme-xs` for headers but badges use `text-sm`).

**Colours** (39-138): `current`, `transparent`, `white #ffffff`, **`black #101828`** (not pure black — `dark:bg-black` on the sidebar therefore renders `#101828`), `brand-25…950` (500 = `#465fff`, 600 = `#3641f5`), `blue-light-25…950` (info), `gray-25…950` + `gray-dark #1a2231` (dropdown panels in dark mode), `orange-25…950`, `success-25…950` (500 `#12b76a`), `error-25…950` (500 `#f04438`), `warning-25…950` (500 `#f79009`), `theme-pink-500 #ee46bc`, `theme-purple-500 #7a5af8`. The default Tailwind palette is **not** reset, so `red-*`, `blue-*`, `pink-*` etc. remain (Next's `AvatarText` uses `bg-pink-100`, `bg-cyan-100`, `bg-green-100`, `bg-purple-100`, `bg-yellow-100` — `TAN/src/components/ui/avatar/AvatarText.tsx:20-27`).

**Shadows** (140-157): `shadow-theme-xs/sm/md/lg/xl`, `shadow-datepicker` (dark range highlight), `shadow-focus-ring` (`0 0 0 4px rgba(70,95,255,.12)`), `shadow-slider-navigation`, `shadow-tooltip`, `drop-shadow-4xl`.

**Z-index scale** (159-165): `z-1, z-9, z-99, z-999, z-9999, z-99999, z-999999`. Usage: overlay `z-9` (`TA/src/partials/overlay.html:4`), sidebar `z-9999` (sidebar.html:3), header `z-99999` (header.html:3), modals `z-99999` (profile-info-modal.html:3), preloader `z-999999` (preloader.html:7), dropdown panels `z-40`. **Header and modal share z-99999** — a modal opened from the header would tie; adminata should reserve a clean ladder (see §6).

### 5.1 Proposed token layer (`adminata.css`)

```css
@import "tailwindcss";
@custom-variant dark (&:is(.dark *));

:root {                                  /* user-overridable, runtime */
  --adminata-brand-500: #465fff;  --adminata-brand-600: #3641f5; /* …25-950 */
  --adminata-font: "Outfit";
  --adminata-radius: 0.5rem;              /* rounded-lg on controls */
  --adminata-radius-card: 1rem;           /* rounded-2xl on cards */
  --adminata-density: 1;                  /* 1 = TailAdmin, .85 = compact */
  --adminata-sidebar-w: 290px; --adminata-sidebar-w-collapsed: 90px;
  --adminata-header-h: 4.5rem;
}
@theme {
  --color-brand-500: var(--adminata-brand-500);   /* etc. */
  --font-sans: var(--adminata-font), ui-sans-serif, system-ui, sans-serif;
  --radius-control: var(--adminata-radius);
  --radius-card: var(--adminata-radius-card);

  --z-index-header: 9990; --z-index-modal: 99999; --z-index-toast: 999999;
}
```

- Tailwind v4 `@theme` variables can reference runtime CSS custom properties, so brand colour, font and radius become **runtime-overridable** by a user stylesheet (`assets.extra_stylesheets`) without a rebuild — this replaces "skins".
- Map the legacy `skin` enum to brand presets: `skin-blue*` → brand `#465fff`, `skin-green*` → success palette, `skin-red*` → error palette, `skin-yellow*` → warning, `skin-purple*` → `theme-purple-500`, `skin-black*` → gray/neutral. `*-light` variants → light sidebar (`bg-white`) vs dark sidebar (`bg-gray-900`). Keep emitting the skin string as a body class so user CSS keyed on it still applies; add `data-adminata-skin`.
- New config keys (additive, in a new `adminata:` tree, not under `sonata_admin`): `theme.mode: light|dark|system|user` (default `user` = toggle persisted in `localStorage['adminata-theme']`, initial from `prefers-color-scheme`), `theme.brand: '#hex'`, `theme.font: 'Outfit'|'system'`, `theme.logo_dark`, `theme.sidebar: light|dark`, `theme.density: comfortable|compact`, `theme.radius: default|sharp|round`, `sidebar.collapsed_default`, `search.shortcut: true`.
- Dark mode: inline `<script>` in `<head>` (before CSS) sets `document.documentElement.classList.toggle('dark', …)` from localStorage/media query to avoid flashes; the header toggle writes the same key. Provide `color-scheme: dark` on `.dark` for native controls.
- Sidebar collapsed state: cookie `sonata_sidebar_hide` (server-side render, BC) **and** `localStorage`; on `lg+` the aside gets `w-[var(--adminata-sidebar-w-collapsed)]`, content `lg:ml-[…]`.
- Density: define control heights and cell paddings through `calc()` with `--adminata-density` (e.g. `h-[calc(2.75rem*var(--adminata-density))]`) or simpler: a `[data-density=compact]` selector overriding a handful of `@utility` rules (`adminata-input`, `adminata-td`).
- Expose **stable class hooks** for users: `adminata-card`, `adminata-btn`, `adminata-btn-primary`, `adminata-input`, `adminata-badge-*`, etc., defined as `@utility` so the long recipes live in one place and Twig stays readable; still emit the legacy Bootstrap class names alongside (`btn btn-primary adminata-btn adminata-btn-primary`) for selector compatibility.

## 6. Accessibility review of TailAdmin markup

Findings (counts from `grep` over `TA/src`): `aria-` 0 occurrences, `role=` 1 (a decorative `role="button"` on an SVG, `form-elements.html:414`), `tabindex` 0, `@keydown` 0, `x-trap` 0, `x-transition` 0, `sr-only` 18 (all for visually-hidden `<input>`s, none for text alternatives), `focus-visible` 2 (both `focus-visible:outline-hidden` — i.e. *removing* focus indication on the datepicker inputs).

| Area | TailAdmin state | Adminata must add |
|---|---|---|
| Dropdowns (header, kebab) | `<button>` without `aria-expanded`/`aria-haspopup`/`aria-controls`; panel is a `<div>`; no ESC; no arrow-key navigation; closes only on outside click | `aria-expanded`, `aria-controls`, `role="menu"/"menuitem"` (or plain links list with `aria-labelledby`), ESC to close + return focus, ArrowUp/Down roving focus, `x-transition`/CSS transition with `motion-reduce`. |
| Modals | no `role="dialog"`, `aria-modal`, `aria-labelledby`; no focus trap; HTML version has no ESC and no scroll lock; close button has no accessible name (icon only) | native `<dialog>` element with `showModal()` gives focus trap, ESC, inert background and top-layer stacking for free (Safari 15.4+, within the Tailwind v4 floor) — recommended; add `aria-labelledby` to `.modal-title`, `<span class="sr-only">Close</span>`. |
| Sidebar | `<nav>` without `aria-label`; submenu toggles are `<a href="#">` with `@click.prevent` (React uses `<button>`); chevron/"…" SVGs unlabeled; collapsed sidebar hides text with `lg:hidden` (icons then have no accessible name); no `aria-current="page"` | `<nav aria-label="Main">`, `<button aria-expanded>` for groups, `aria-current="page"`, `title`/`sr-only` labels on icons when collapsed, keep `.menu-item-text` in DOM as `sr-only` instead of `hidden` when collapsed. |
| Header toggles | hamburger/app-menu/dark-mode/notification buttons have no text (React adds `aria-label` on hamburger only) | `aria-label` + `aria-pressed` (dark mode), `aria-expanded` (hamburger, notifications). |
| Forms | labels not associated (`<label>` without `for`, inputs without `id`) except checkbox demos; error text not linked (`aria-describedby`/`aria-invalid` absent); password toggle is a `<span @click>` (not focusable); custom select chevron fine (`pointer-events-none`); multiselect (HTML) has no keyboard support (React version has combobox/listbox roles + arrows/Enter/Escape) | Symfony form theme already emits `for`/`id`; add `aria-invalid="true"` + `aria-describedby` to error messages in `form_row`; make toggles `<button type="button" aria-label>`; use Tom Select (keyboard-complete). |
| Tables | `<th>` without `scope="col"`; header text wrapped in `<p>` inside `<div>` (semantically odd); no `<caption>` | `scope="col"`, sortable headers as `<a aria-sort="ascending|descending|none">`, batch checkbox `aria-label="Select row N"`. |

| Skip link, landmarks | none (`<main>` present, no `<header>` landmark label, no skip link) | `<a class="sr-only focus:not-sr-only …" href="#main">Skip to content</a>`; `aria-label`s. |
| Viewport | `user-scalable=no, maximum-scale=1.0` (`index.html:7`) — blocks zoom, WCAG 1.4.4 failure; Sonata has the same meta (`standard_layout.html.twig:34`) | remove `user-scalable=no`/`maximum-scale`. |
