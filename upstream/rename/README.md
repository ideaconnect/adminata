# The rename engine

`apply.php` rewrites every identifier adminata inherited from Sonata to its IDCT\Adminata name
(PLAN/v2/02). It renamed this repository, the ORM layer and the MongoDB layer on 2026-09-12, it
renames an application (`vendor/bin/adminata-rename`, UPGRADE.md §10), it translates every upstream
release before `upstream/sync.sh` merges it, and in `--check` mode it is the `make check-names` gate.

| File | What it is |
|---|---|
| `rules.php` | the ordered PCRE rules, each `all` (unambiguous everywhere) or `tree` (adminata's own trees only) |
| `allow.php` | files the engine skips, phrases it keeps (attribution, other Sonata bundles), the five retired bundle names it reports on an application |
| `known.txt` | generated by `build-lists.php` from the Sonata-named trees: the exact names adminata, the ORM layer and the MongoDB layer own — what application mode rewrites |
| `Engine.php` | the class; no autoloader, `apply.php` requires it |
| `apply.php` | the command line |

```console
$ php upstream/rename/apply.php --tree .                 # one of adminata's own trees
$ php upstream/rename/apply.php --app --dry-run <app>    # an application: what would change, and its own names
$ php upstream/rename/apply.php --check [--app] <dir>    # the gate: exit 1 while anything is left
$ php upstream/rename/apply.php --stdin --as src/Foo.php  # one file's content (upstream/sync.sh)
$ php upstream/rename/apply.php --path src/SonataFoo.php  # one path
```

## Adding a rule

A rule is `['scope' => 'all'|'tree', 'pattern' => <PCRE without delimiters>, 'replacement' => …]`,
optionally with `globs` or `not_globs` matched against the file name. Put it before the general
rule that would otherwise eat its match, and add a case to `tests-adminata/Unit/Rename/EngineTest.php`.
A name that lives in `src/` also belongs in `known.txt`: rerun `build-lists.php` against a
checkout at the last Sonata-named commit (`git worktree add /tmp/old <sha>`), because the lists
are read from the *old* spellings.

The Twig-namespace rules, the namespace rules and the explicit names are `all`; the families
(`sonata_…`, `sonata.…`, `sonata-…`, `Sonata…`) are `tree`, so that an application's own
`sonata.admin.<x>` id or `sonata-<x>` class is reported rather than rewritten — a renamed admin id
renames the `ROLE_*` names derived from it (UPGRADE.md §6.3).
